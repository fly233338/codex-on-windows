# 目的

- 审核 `docs/PLAN.md` 的实施情况。
- 根据当前仓库验证用户评审中的每一条结论。
- 通过配套的 `$sol-plan-for-luna` skill 生成下一份实施计划。
- 仅在 Plan Mode 下运行。
- 不要修改任何被仓库追踪的文件，也不要直接实施修复。

## 前置条件

必须具备：

- 当前仓库。
- `docs/PLAN.md`。
- 配套的 `$sol-plan-for-luna` skill。

如果缺少任何一项，立即停止并向用户索取。不要自行重建缺失的计划，也不要编造评审发现。

## 必须完整阅读

完整阅读以下内容：

1. 配套的 `$sol-plan-for-luna` skill。
2. `docs/PLAN.md`。

## 审核流程

- 将 `docs/PLAN.md` 转换为内部需求检查清单。
- 提取适用于计划涉及文件和模块的 `AGENTS.md` 中的代码风格、实现方式、测试要求及其他实施约束，并将其作为内部审核约束。
- 检查当前实现以及用户评审建议是否符合这些 `AGENTS.md` 约束。
- 根据当前仓库检查每一项需求。
- 将用户评审中的每一条结论映射到计划和实际实现。
- 直接检查评审中引用的实现内容。
- 在存在相关检查命令时，运行非修改性的检查。
- 明确区分静态检查结果与实际执行过的命令结果。
- 即使用户评审只覆盖了计划的一部分，也要继续审核完整计划。

在内部将发现分类为：

- 已验证完成。
- 已确认问题。
- 部分正确，或需要调整。
- 错误、已过时，或不建议采用。
- 无法验证。

## 修订内容选择

- 只纳入尚未解决的正确性、兼容性、测试、打包、CI 或可维护性工作，以及影响约束中代码风格的问题。
- 排除已经完成的需求。
- 排除被否决的评审建议。
- 排除成本高于其已证明价值的清理工作。
- 除非评审指出了具体缺陷，否则保留当前已经正常工作的设计。
- 当所有已确认需求都已经对应到具体任务和验收测试后，停止继续扩展修订范围。

## 修订后的计划

使用 `$sol-plan-for-luna` skill 生成一份完整的替代计划。

修订后的计划必须：

- 能够独立供 Luna 工作代理使用。
- 只包含剩余工作。
- 保留相关的兼容性要求和接口要求。
- 明确指定具体测试和验收标准。
- 避免重复 `docs/PLAN.md`、架构文档、能力文档或 `AGENTS.md` 中已有的内容。

## 输出

只返回一个 `<proposed_plan>` 块，不要添加任何解释性前言。

必须包含以下章节：

1. Title。
2. Review Conclusion。
3. Revision Work。
4. Test and Acceptance。
5. Assumptions。

`Review Conclusion` 中只能包含：

- 用于说明当前状态所必需的、按组整理的已验证基线。
- 会影响新计划的已确认发现或经过调整的发现。
- 必须明确说明被排除原因的已否决发现。
- 会影响结论可信度的验证限制。

不要输出完整的内部需求矩阵。
